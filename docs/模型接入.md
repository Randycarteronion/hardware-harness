# 模型接入指南 —— 本地 llama.cpp 与 DeepSeek API 双通道

> 本文回答"Hardware Harness 怎么调模型"。适用版本：2026-08-23。
> 配套代码：`src/harness/llm.py`（客户端）、`src/harness/agent.py`（循环）、
> `src/harness/cli.py` 的 `agent` / `agent-serve` 命令。

---

## 一、架构：一个客户端，两个 Provider

两个 Provider 的 API 协议完全同构（OpenAI 兼容 /chat/completions），
所以只需要一份实现 + 一份配置：

```
harness agent "目标"
        │
        ▼
  agent.py ── tool-calling 循环（8 个硬件工具，与 MCP 同一份实现）
        │
        ▼
  llm.py（OpenAI 兼容客户端，urllib 实现，零新依赖）
        │
        ├── provider=local    →  http://127.0.0.1:8080/v1
        │                        （llama-server，本机 C:/llama，Qwen3-8B GGUF）
        │
        └── provider=deepseek →  https://api.deepseek.com
                                 （deepseek-chat / deepseek-v4-flash）
```

**切换就一个字段**，两种方式任选：

```bash
# 方式 A：环境变量（临时/CI）
set HARNESS_AGENT_PROVIDER=deepseek     # 或 local
set DEEPSEEK_API_KEY=sk-xxxx            # deepseek 必需；local 不需要

# 方式 B：项目根 agent.toml（持久）
[agent]
provider = "local"
model = "qwen3-8b"
# base_url = "https://api.deepseek.com"
```

优先级：环境变量 > agent.toml > 默认（local）。
**API key 只从环境变量读，绝不写文件**（密钥不落盘）。

## 二、用法

### 本地大脑（llama.cpp）

```bash
harness agent-serve                 # 拉起 llama-server（--jinja 开 tool-calling）
harness agent "列出硬件设备并总结"
harness agent "跑 motor_start 测试并告诉我结果"
```

`agent-serve` 的启动参数与 `C:/llama` 实际安装对齐（可在 agent.toml
覆盖 `llama_server_exe` / `llama_model` / `llama_ngl` / `llama_ctx`）。
**`--jinja` 是必须的**：它启用模型自带的 chat template，Qwen3 的
tool-calling 依赖它；不带 jinja 裸启的服务器会拒收 tools 字段。

### API 大脑（DeepSeek）

```bash
set HARNESS_AGENT_PROVIDER=deepseek
set DEEPSEEK_API_KEY=sk-xxxx
harness agent "验证 ESP32 电机能到 1000 rpm"
```

不需要 agent-serve（没有本地服务器要起）。

### 危险操作的人工确认流

Agent 调 `hardware_flash` 无 token 时工具层直接拒绝（三道闸不变）。
系统提示词会让 LLM 改为输出 `ASK_CONFIRM: <理由>`，CLI 暂停并弹
`允许执行？[y/N]`，你批准后它才带 `confirm_token` 重试。
**LLM 只能请求批准，永远无法自批** —— 这是安全模型的底线。

每次运行的完整对话落盘 `runs/agent_<时间>/transcript.md`（过程即
artifact，排错第一现场）。

## 三、本机实测记录（2026-08-23，重要）

**这台笔记本（RTX 3050 Laptop 4GB / 16GB RAM）目前跑不动 8B 本地模型。**
三级实测数据，引以为鉴（详见 lessons L23/L24）：

| 尝试 | 结果 |
|---|---|
| `-ngl 99` 全层上 GPU | OOM：需 4.46GB，卡只有 4GB |
| `-ngl 22` / `-ngl 10` 部分卸载 | 仍 OOM：WDDM 下实际可分配 <1.5GB（`nvidia-smi` 报的 free 不可信；ChatGPT 桌面版等占着）|
| `-ngl 0` 纯 CPU | 模型加载把系统内存压爆（当时仅剩 4.3GB 空闲，需 ~6GB），进程被杀 |

**在本机跑通本地大脑的三个解锁路径（任选一）：**
1. **关应用腾内存**：关掉大型占内存程序（浏览器多开、ChatGPT 桌面版等），
   腾出 ≥6GB 空闲 RAM 后 `harness agent-serve`（默认已是 CPU 模式），
   8B Q4 约 4~10 tok/s，可用但慢
2. **换小模型**：下载 Qwen3-4B Q4（约 2.4GB，CPU 轻松跑）放到
   `C:/llama`，agent.toml 里改 `llama_model` 指向它。注意本机网络
   到 HF/hf-mirror 不通、ModelScope 没有官方 GGUF——需要你手动找渠道
3. **换大显存机器**：≥8GB 显存台式卡直接 `llama_ngl = 99` 全卸载，速度起飞

**不折腾本地就切 DeepSeek**（方式见上节）—— 你的 DSH 配置里
`deepseek-v4-flash` 就是现成的，key 一设就能用。

代码正确性不受影响：Agent 循环已用进程内假 LLM 服务器做了协议级
端到端测试（真 HTTP / 真 OpenAI 格式 / 真工具执行，5 个测试），
任何符合协议的后端接上即用。

## 四、DSH 对接说明

**现状盘点（2026-08-23 实测）：**
- `C:/Users/18754/.dsh/settings.yaml` —— DSH 的运行时配置，已经配好
  两个 provider：
  - `local`：`http://127.0.0.1:8080/v1`（llama.cpp，Qwen3-8B）
  - 默认模型：`deepseek-official / deepseek-v4-flash`
- `C:/Users/18754/Desktop/DSH` —— **空目录**，GitHub Desktop 那次
  拉取没有成功落下源码（如需研究 DSH 源码请重新 clone）

**对接方式：DSH 当 Agent Host，Hardware Harness 当工具层（MCP）。**

DSH 的模型配置已经就绪（就是上面那份 settings.yaml，两边指向同一个
llama-server / DeepSeek，行为一致）。要让它操作硬件，把 harness-mcp
注册为 DSH 的 MCP server：

```json
{
  "mcpServers": {
    "hardware": {
      "command": "harness-mcp",
      "args": []
    }
  }
}
```

（具体落在 DSH 的哪个配置文件取决于版本——settings.yaml 或其
profiles 目录；DSH 源码不在本机，无法给出精确路径，重新拉取仓库后
按其文档的 MCP 配置节填入即可。）

之后 DSH 对话里说"用 hardware 工具列出设备/跑测试"，它就会调
`hardware_list_devices` / `hardware_run_test`。8 个工具与
`harness agent` 内置大脑用的是**同一份实现**（TOOL_FUNCS 注册表），
行为不会分叉。

**两条路线怎么选：**

| 路线 | 适合场景 |
|---|---|
| `harness agent`（自带大脑） | 脚本化/CI 场景，一条命令闭环，不依赖任何 Agent Host |
| DSH / Claude Code + harness-mcp | 交互式对话，复用 Host 的代码编辑等能力（改代码→烧录→验证全在对话里）|

## 五、配置参考（agent.toml 全字段）

```toml
[agent]
provider = "local"              # local | deepseek
base_url = "http://127.0.0.1:8080/v1"
model = "qwen3-8b"              # deepseek 时用 deepseek-chat 等
temperature = 0.3               # 硬件操作要稳

# 仅 local（agent-serve 用）：
llama_server_exe = 'C:\llama\llama-b10545-bin-win-cuda-12.4-x64\llama-server.exe'
llama_model = 'C:\llama\QwenQwen3-8B-GGUF\Qwen3-8B-Q4_K_M.gguf'
llama_ngl = 0                   # 本机 4GB 卡实测只能 0；≥8GB 卡改 99
llama_ctx = 8192
port = 8080
```
